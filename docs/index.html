Hardware-first multimedia,
glass to glass, in Rust.

Write a video or audio pipeline once and run it on a microcontroller, a real-time OS, a server, a GPU, or in the browser. The core is pure Rust, needs no operating system, and can run without a heap. Frames stay in hardware memory instead of being copied around. Running an ML model is just another stage in the pipeline.

Design

Four ideas the whole framework is built on.

The one number that matters here is glass-to-glass latency: the time from light hitting the camera sensor to a pixel showing up on a screen. Everything below is there to keep that number small.

01

Everything is async

Each element is a Rust future. The framework never spawns threads of its own, so it runs under whatever executor you already use: Tokio on a server, Embassy on a microcontroller, the event loop in a browser. Every link has a small queue with backpressure, and a pipeline can spread across CPU cores when it needs to.

02

Frames stay where the hardware put them

A decoded frame in GPU memory should not take a round trip through the CPU on its way to the screen. Each link negotiates where its frames live (system RAM, DMABUF, Vulkan, CUDA, Direct3D, WebGPU). When two neighbours agree, nothing is copied. When they cannot, a converter is inserted automatically, so every copy that remains is one you can see in the graph.

03

No OS required, heap optional

The core does not depend on an operating system, so the same pipeline shape runs on a bare-metal Cortex-M, under FreeRTOS or Zephyr, on a Linux server, and in WebAssembly. On a microcontroller it links no allocator at all. Network protocols are parsed separately from the sockets that carry them, so the same parser works on a socket, a DMA buffer, or a test file.

04

ML is a first-class element

An inference model is an element in the graph. Tensors are negotiated between elements the same way video formats are, so a preprocess stage, a model, and a postprocess stage chain together with no special casing, and the tensors can stay on the GPU throughout.

🔗

Format negotiation

Two connected elements have to agree on a frame format and on where the frame lives in memory. Instead of settling that link by link, a small constraint solver picks an answer for the whole graph at once. Branches that split and rejoin stay consistent, and when no answer exists the error names the link that could not agree. If a format changes mid-stream, only the affected part is solved again.

Clock and sync

Core
🔋

Microcontrollers, no heap

The no-heap build links no allocator and cannot panic. CI checks both, along with a flash, RAM, and stack budget, by running the pipeline on an emulated Cortex-M.

Capture runs off interrupts and DMA. A supervisor handles peripheral faults and only feeds the watchdog while frames are actually moving. RTP receive with a jitter buffer works without a heap too. For certified products there is a safety case, and CI checks that every proof it cites still exists.

Targets

One pipeline. MCU → RTOS → CPU → GPU → WASM.

The graph you write is the same on all five. What changes is the shell around it: which executor drives it and which hardware elements fill the stages. PORTABILITY.md shows one detection-overlay pipeline built for native and for the browser from a single definition.

🔌

Microcontroller

No heap, no allocator, no panics, and a flash, RAM, and stack budget that CI enforces on an emulated Cortex-M.

⏱️

Real-time OS

The same static pipeline under Embassy, FreeRTOS, or Zephyr, with the Zephyr module dropping straight in.

☁️

CPU

Tokio on servers and edge boxes, with the full element and protocol set and each OS's hardware decoder: NVDEC or VAAPI on Linux, Media Foundation on Windows, VideoToolbox on macOS, MediaCodec on Android.

⚡

GPU

Vulkan Video decode, native NVIDIA codecs, and a CUDA to wgpu bridge keep frames on the card. Plugs into an app's existing wgpu device. Packaged for Bevy as bevy-g2g.

🌐

Browser

WebSocket or WebRTC in, WebCodecs decode, canvas or WebGPU out. A whole graph can run in a worker. ML runs in the browser or on a server.

🛡️

QNX

The safety-certified RTOS used in cars and medical devices. The core and the baseline element set compile for it with no code changes. Not yet run on hardware.

🎯

One API

Same element trait, same formats, same negotiation, same runner. Move a stage between browser, edge, and server by swapping one element.

Quickstart

Six lines from clone to live pixels.

Pick a pipeline shape, enable the right cargo features, and run. Step-by-step recipes for every shape (RTSP, NVDEC, KMS, VAAPI, ML) are in the README. 

# Cargo.toml
[dependencies]
g2g-core    = { git = "https://github.com/Glass2GlassHQ/glass2glass" }
g2g-plugins = { git = "https://github.com/Glass2GlassHQ/glass2glass", features = ["rtsp", "ffmpeg", "wayland-sink"] }

// main.rs
use g2g_core::runtime::{run_source_transform_sink, LatencyProfile};
use g2g_plugins::{RtspSrc, ffmpegdec::{FfmpegH264Dec, OutputFormat}, WaylandSink};

let src  = RtspSrc::new("rtsp://localhost:8554/pattern");
let dec  = FfmpegH264Dec::new().with_output_format(OutputFormat::Nv12);
let sink = WaylandSink::new();

run_source_transform_sink(src, dec, sink, &clock, LatencyProfile::Live).await?;
# Linux + NVIDIA; zero PCIe round-trip after decode.
[dependencies]
g2g-plugins = { git = "...", features = ["rtsp", "ffmpeg", "cuda", "cuda-gl"] }

use g2g_plugins::{RtspSrc, ffmpegdec::{FfmpegH264Dec, Backend}, CudaGlSink};

let src  = RtspSrc::new(url);
let dec  = FfmpegH264Dec::with_backend(Backend::NvdecCuda);  // MemoryDomain::Cuda
let sink = CudaGlSink::new();                          // EGL + NV12 shader

run_source_transform_sink(src, dec, sink, &clock, LatencyProfile::Live).await?;
# RTSP -> decode -> GPU preprocess -> ORT (CUDA EP) -> classification.
[dependencies]
g2g-plugins = { git = "...", features = ["rtsp", "ffmpeg"] }
g2g-ml      = { git = "...", features = ["wgpu", "cuda"] }

use g2g_core::runtime::run_linear_chain;
use g2g_ml::{WgpuPreprocess, OrtInference, TensorPostprocess};

let src       = RtspSrc::new(url);
let mut dec   = FfmpegH264Dec::new().with_output_format(OutputFormat::Nv12);
let mut pre   = WgpuPreprocess::new(w, h);                       // NV12 -> f32 NCHW
let mut infer = OrtInference::from_memory_with_cuda(model)?;
let mut post  = TensorPostprocess::topk_classification(5);

run_linear_chain(src, vec![&mut dec, &mut pre, &mut infer, &mut post],
                 FakeSink::new(), &clock, LatencyProfile::Live).await?;
# Loopback-verified; honors receive-side NACK by retransmit.
[dependencies]
g2g-plugins = { git = "...", features = ["udp-egress", "mf-encode"] }

use g2g_plugins::{VideoTestSrc, MfEncode, UdpSink};

let src  = VideoTestSrc::new(1920, 1080, 30, 0);              // RGBA test pattern
let enc  = MfEncode::new().with_hardware();              // Windows; on Linux use NvEnc / ffmpeg
let sink = UdpSink::new("239.0.0.1:5004".parse()?)
            .with_rtp(96, 0x1234_5678);                     // payload type, SSRC

run_source_transform_sink(src, enc, sink, &clock, LatencyProfile::Live).await?;
# wasm32-unknown-unknown; needs --cfg=web_sys_unstable_apis for WebCodecs.
[dependencies]
g2g-plugins = { git = "...", features = ["web", "web-codecs"] }

use g2g_plugins::{WebSocketSrc, H264Parse, WebCodecsDecode, CanvasSink};

// Browser glass-to-glass: WS bytes -> parse -> WebCodecs -> canvas.
let src        = WebSocketSrc::new("wss://feed.example.com/h264", h264_caps);
let mut parse  = H264Parse::new();
let mut decode = WebCodecsDecode::new();
let sink       = CanvasSink::new("video-canvas");

wasm_bindgen_futures::spawn_local(async move {
    run_linear_chain(src, vec![&mut parse, &mut decode], sink, &clock, profile)
        .await.unwrap();
});
# A declarative graph (JSON/YAML) or a Rhai builder script -> the same Graph.
g2g-launch --graph pipeline.yaml
g2g-launch --script build.rhai

# scriptrouter: route each buffer to your own code, per decision. route()
# returns one port, a negative to drop, or an array of ports to multicast.
g2g-launch videotestsrc num-buffers=8 ! \
    scriptrouter name=r script="fn route(f){ f.sequence % 2 }" \
    r. ! appsink channel=even   r. ! appsink channel=odd

// Pull each channel live (Rust / C / Python) while the pipeline runs:
let even = register_appsink_pull("even");
while let Some(frame) = even.pull().await { /* feed your consumer */ }
